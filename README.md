# Endless Runner 2D

Endless Runner 2D is a Chrome-dino-style browser game rebuilt from a beginner p5.js sketch into a fully typed TypeScript + Canvas2D project. A three-frame T-rex sprints across a scrolling desert, jumping cacti that spawn from either a seeded random stream or a deterministic pattern generated by a Python script — the same JSON fixture the test suite pins. The simulation runs on a fixed-timestep loop, so physics and scoring stay identical at any framerate, with a menu → playing → game-over state machine, an inset-hitbox AABB collision system, and a difficulty curve that scales ground speed with score. A live settings panel tunes gravity, jump velocity, night mode, and pattern mode; best score and a top-five scoreboard persist in localStorage. Built with Vite, linted with ESLint + Prettier, unit-tested with Vitest, and verified by GitHub Actions CI on every push. Deploys to Vercel as a static build with zero extra configuration.

## Controls

| Input | Action |
| --- | --- |
| `Space` / `↑` | Start run · jump |
| Click / tap canvas | Start run · restart after game over |
| Settings button | Tune jump velocity, gravity, night mode, pattern mode |

## How it works

- **Fixed-timestep loop** (`src/core/loop.ts`) — simulation advances in constant 1/60s steps
  while rendering happens once per animation frame; long frames are clamped so a background
  tab doesn't fast-forward the game.
- **Central config** (`src/config.ts`) — every tunable (canvas size, gravity, speed curve,
  spawn gaps, hitbox insets, sprite sizes) lives in one typed object. No magic numbers in
  game code.
- **Difficulty curve** — ground speed is `base + perPoint × score`, capped at `max`
  (`src/systems/score.ts`), so runs ramp smoothly from 340 px/s to 820 px/s.
- **Spawning** (`src/systems/spawner.ts`) — distance-based, not frame-based. Two modes:
  random gaps drawn from a seeded mulberry32 RNG, or a deterministic pattern replayed from
  `public/patterns/default.json`.
- **Collision** — AABB with per-sprite hitbox insets so near-misses feel fair
  (`src/core/math.ts`).
- **Persistence** — best score and a top-5 scoreboard in `localStorage`, with corrupt-data
  fallbacks (`src/systems/storage.ts`).

## Deterministic obstacle patterns

`scripts/gen_obstacles.py` emits a reproducible obstacle sequence using a plain LCG
(same seed ⇒ same JSON on any platform):

```bash
python scripts/gen_obstacles.py --seed 20260925 --count 64
```

The shipped `public/patterns/default.json` is both a game asset (enable
**Deterministic pattern mode** in settings to replay it) and a pinned test fixture —
`tests/spawner.test.ts` asserts its seed, bounds, and first entries.

## Tech stack

TypeScript (strict) · Vite · Canvas2D · Vitest · ESLint (flat config) + Prettier ·
GitHub Actions · Python 3 (pattern generator)

## Local development

```bash
npm install
npm run dev        # start dev server
npm test           # run unit tests
npm run lint       # eslint
npm run build      # typecheck + production build
npm run preview    # serve the production build
```

## Testing

Vitest covers the core logic: AABB/inset collision math, the score-to-speed curve and
framerate-independent score accumulation, spawner behaviour in both modes (pattern replay,
overshoot carry, RNG determinism), and scoreboard persistence including corrupt-data cases.
CI runs lint, tests, and build on every push.

## Deploy

The repo ships a `vercel.json` configured for the Vite static build:

```bash
npm i -g vercel   # once
vercel deploy
```

No further setup required — Vercel picks up `npm run build` and serves `dist/`.

## Project history

Originally a 2021 p5.js course sketch ("Add files via upload"). Rebuilt in 2026 with a
